What a gate looks like

Models are allowed to be wrong. The pipeline is not. So a model never writes to the trusted layer; it proposes, and a deterministic check decides. Here is one gate from a system I run every week — the one that repairs a parser after an upstream site changes its payload.

DETECTA raw payload the current parser cannot read — it raises, or returns zero records while carrying structure the last known-good payload never had.
PROPOSEAn agent reads the old parser, a structural diff of old vs. new payload, and a sample — and proposes a replacement parse(raw).
GATEThe patch must reproduce the current parser byte-for-byte on the last known-good raw file, and emit schema-exact, non-empty records on the drifted one. No imports. No I/O.
DISPOSEPass: promoted, content-addressed, with the original kept as fallback. Fail: recorded and rejected — the agent never retries the same drift silently.
RESULTEvery run replays identically. The model wrote the code; the gate decided whether it ships.

The same shape governs entity matching (verdicts cached once, read forever, humans review the low-confidence tail) and narration (any number not in the precomputed fact pack is a hard reject).
