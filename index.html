01 · Governed Data Platform

Governed Data Platform

  • data in motion
  • profiles
  • lineage on every run
  • release sets by authority

Profile-driven governance for data as it passes through: a data plane, not a catalog. A profile declares what a dataset must contain and which controls apply; the platform enforces it, applies lineage to every run without exception, and publishes what it enforced. One upload becomes a release set, with each recipient receiving the projection their authority entitles them to. A machine may propose a profile; only a named person approves one.

  • ODCS-shaped profiles · OpenLineage on every run
  • §222 · Carpenter · E.O. 13526 · §2.3
  • KLV · Remote ID · SAPIENT read by their bytes

02 · AI Evidence Record + Model Evidence

AI Evidence Record + Model Evidence

  • clinical trials
  • tamper-evident ledger
  • classifier acceptance

A tamper-evident ledger that sits beside a clinical trial's data systems. Every AI-generated output is quarantined until a credentialed human signs it; seven rules scan the ledger for what an inspector would find, and a per-study AI Evidence Datasheet cites the clause each row satisfies. Edit one byte and verification names the broken sequence number. Model Evidence is the companion judge: give it a classifier's predictions and a policy and it returns Pass, Fail or Insufficient evidence, with exit codes CI can gate on.

  • SHA-256 hash chain · 7 exception rules
  • 21 CFR Part 11 · ICH E6(R3) · ALCOA+
  • Pass / Fail / Insufficient · CI exit codes

03 · edshield + edshield-evidence

edshield + edshield-evidence

  • student privacy
  • on-device NER
  • protected bench

A local-first student-privacy layer for AI in education. edshield detects and removes student PII from essays, tutoring transcripts and chat messages before the text reaches any language model, on a laptop CPU or inside a Chromebook browser, so no student text leaves the device. Rules handle the identifiers where regex plus validation wins; a PIILO-trained DeBERTa model is the authority on names. edshield-evidence is the protected bench: it measures what still survives in the final output and hands the rows to a fixed judge for the verdict.

  • Recall 1.000 · 0 of 165 missed on 680 held-out essays
  • FERPA · COPPA · research policies
  • Apache-2.0 · on PyPI · ONNX in the browser

04 · corpuscle

corpuscle

  • corpus datasheet
  • signed evidence
  • agents propose, core disposes

An agentic corpus datasheet. Agents plan the scan, investigate the findings and brief the authorizing official, on top of a deterministic, signed measurement core. The core hashes every document, builds a Merkle root, measures duplication, gates findings against a versioned policy and signs the result as an in-toto statement. The bundle travels with the corpus and verifies offline with a directory, the bundle and a public key. An agent's investigation is recorded and signed beside the numbers, and nothing it proposes takes effect until a named approver accepts it.

  • Ed25519 · DSSE over an in-toto statement
  • 97 metric IDs across ten families
  • Verifies offline: directory + bundle + public key

06 · RxGuard

RxGuard

  • pharmacy margin
  • FHIR R4B
  • gated explanations

Evidence-first pharmacy margin and exception analysis. RxGuard joins what a payer returned, what the pharmacy paid and what changed later, then flags loss-making fills, unresolved reversals, rejected claims and incomplete audit packets. Every number carries a source reference; an explanation, whether written by the offline baseline or a model, cannot mention a dollar that is absent from the computed fact pack. The MFP Refund Ledger applies the same engine to Medicare's negotiated-price refunds: expected refund, received, variance and aging per fill, with a dispute-ready evidence pack.

  • FHIR R4B EOB · CARIN Blue Button Pharmacy EOB 2.2.0
  • 6 reproducible scenarios · 47-fill MFP ledger
  • CycloneDX SBOM · MIT

07 · retro + learned-behavior

retro + learned-behavior

  • Claude Code skill
  • agent memory
  • no LLM in the loop

Two tools that make an AI coding agent's lessons durable. learned-behavior observes what the agent does through Claude Code hooks, mines recurring failures and self-corrections into rules, surfaces them before the next task, and promotes or decays them on behavioral signal alone: one local SQLite file, nothing leaves the machine. retro is the curation layer above it: a structured retrospective at project milestones, human-gated, that scopes each lesson to project, stack or global and holds the cross-project playbook to a fixed budget.

  • 25-slot playbook · a lesson must displace one to enter

Production at scale · Mobius

A fraud pipeline live since 2015, at 3 billion call records a day

SIM-box call-bypass fraud detection for multiple mobile operators in West Africa, re-architected from an hourly batch into a streaming Hadoop/Spark pipeline, and still in production.

Problem

A Java SIM-box call-bypass fraud detector running as a two-server hourly batch. Detections lagged over an hour, customers' own analysts found misses after the fact, and multiple $300K/year accounts were about to churn to a competitor.

What I built

Re-architected it as a Hadoop/Spark pipeline scoring every 30-minute CDR window against 24 hours of per-MSISDN history with an inline rules engine, plus a redesigned Node.js UI where customers author their own detection rules. Per-customer deployments sized to volume; early namenode failures moved to an HA cluster.

Outcome
  • Detection latency 1h+ → under 30 min
  • Largest deployment 28 nodes at 3B+ voice CDRs/day, later 50B+ SMS/day (1B+ per 30-minute window)
  • Same pipeline reused for A2P/OTP SMS bypass fraud
  • Live since 2015 and still in production; the at-risk accounts stayed
  • Hadoop
  • Spark
  • HBase + Phoenix
  • MongoDB
  • Node.js
  • AWS (S3, Lambda, EMR)
