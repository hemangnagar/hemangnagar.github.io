Open source · adversarial AI · deterministic control

AI can argue forever. Decisions cannot.

Decision Gate takes an idea, identifies what must be true, tries to break those assumptions, and then stops. The models generate the arguments; a fixed rule turns the remaining problems into ACT, WAIT, or ABANDON.

The easiest way to see the value is through two decisions we actually made.

See the two decisionsView source

How it works

Decision 1 — we did not build the healthcare idea

Real decision · healthcare

Build a cardiology-first agent for orders → authorization → scheduling → prep → procedure → results → follow-up.

ABANDON
Why it looked good

The workflow is painful, fragmented, expensive, and full of manual handoffs. A focused AI agent sounded like a strong product opportunity.

What the review found

Fatal problem: companies already sell much of the core workflow we were proposing.

Tennr already moves patients through referrals, insurance requirements, authorizations, diagnostics and scheduling. Honey Health already automates prior authorization for procedures, imaging and diagnostics from requirement detection through submission and follow-up. Silna also automates prior-authorization submission and follow-up.

TennrHoney HealthSilna
Why that matters

The problem is real, but “the problem exists” is not the same as “we have a differentiated product.” We had not shown a clear capability customers could not already buy.

Rule trace
problem = “core workflow already exists in market; differentiation not established”
severity = FATAL
status = UNRESOLVED
matched rule = unresolved FATAL → ABANDON
Decision
ABANDONDo not spend engineering time building this product as proposed. A future healthcare idea would need a clearly different wedge and should be treated as a new decision.

Decision 2 — why we did build Decision Gate

Real decision · this project

Build a small open-source control layer that turns AI-assisted analysis into a bounded, auditable decision.

ACT
What we rejected first

We did not decide to build “another multi-agent debate framework.” Systems for agents debating, critiquing, reflecting and orchestrating already exist. That alone was not interesting enough.

What remained useful

The narrower problem survived the challenge: AI can keep generating objections without ever telling the user when enough analysis is enough. We wanted a control layer that:

1. records the claims and important objections,
2. stops review using an explicit policy,
3. maps unresolved problems to ACT / WAIT / ABANDON with fixed rules,
4. records exactly why the decision was made,
5. reopens only when something materially changes,
6. later compares the reasoning with what actually happened.

Remaining risk

Material but not fatal: the outcome-scoring idea only becomes truly useful after we accumulate enough real decisions and later observe what happened.

That is a reason to measure the project, not a reason to block the MVP.

Rule trace
fatal unresolved problems = 0
blocking unresolved problems = 0
material accepted risk = “needs enough real decisions to score usefulness”
matched rule = no unresolved fatal/blocking problem → ACT
Decision
ACTBuild the smallest MVP, use it on real decisions, and let later outcomes tell us whether the reasoning process is actually useful.
The important difference: healthcare failed because the proposed product itself did not have enough differentiation. Decision Gate survived only after we removed the generic “agents debate” idea and narrowed the project to explicit stopping, deterministic action rules, decision history, controlled reopening, and outcome scoring.

The final rule is deliberately simple

IF an unresolved problem would make the idea fundamentally wrong → ABANDON ELSE IF an unresolved problem must be fixed before acting → WAIT ELSE → ACT Important but non-blocking uncertainty is recorded as accepted risk. The matched rule and the problems that triggered it are written into the ledger.
