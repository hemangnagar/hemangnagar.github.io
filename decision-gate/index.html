Open source · adversarial AI · deterministic control

AI can argue forever. Decisions cannot.

Decision Gate turns open-ended adversarial reasoning into an auditable decision protocol. Models identify claims and attack assumptions; fixed rules decide whether the result is ACT, WAIT, or ABANDON.

The value is not “three options.” The value is that the final action is mechanically traceable to unresolved evidence instead of being another model opinion.

What the system adds

01 · structure

Turns debate into state

Claims, dependencies, challenges, severity, resolution conditions, accepted risks, and the stop reason are stored in a ledger instead of disappearing into chat history.

02 · control

The model cannot move the goalposts

Models may propose reasoning. They cannot override the gate. An unresolved FATAL challenge is an ABANDON, every time.

03 · closure

Reasoning has a stopping condition

Once the decision is closed, another model objection does not restart the argument. Reopening requires a declared material trigger.

The control flow

There is no “judge model” hidden after the adversary. The last reasoning step is a rule evaluation over ledger state.

A worked decision: the original idea gets rejected

This is the important distinction the earlier page obscured. A FATAL challenge does not magically turn into “build the MVP.” The original decision is rejected. A materially different proposal must be submitted as a new decision.

Build a generic multi-agent adversarial debate framework.

CL-001 — Generic multi-agent debate is differentiated enough to justify a new open-source project.
Adversary
FATAL · CH-001
Direct prior art already covers multi-agent debate, critic/reflection loops, and adversarial orchestration. The core thesis is not differentiated.
Resolution state
UNRESOLVED
resolves_if: demonstrate a materially different lifecycle or control mechanism that existing debate/orchestration systems do not provide.
Gate trace
unresolved = [CH-001]
CH-001.materiality = FATAL
matched_rule = unresolved FATAL → ABANDON
Final action
ABANDONThe generic debate-framework decision is closed. No model gets to override this result.
So why does Decision Gate itself exist?The later proposal was not “try the same idea again.” It was a new decision: build a bounded adversarial decision ledger with deterministic stopping, controlled reopening, and outcome scoring. That proposal went through its own review. The ledger keeps those pivots separate so a failed thesis cannot be retroactively rewritten as a success.

The gate is intentionally boring

IF any unresolved challenge is FATAL → ABANDON ELSE IF any unresolved challenge is BLOCKING → WAIT ELSE → ACT # MATERIAL and NON_BLOCKING items are preserved as accepted risk. # The matched rule, unresolved IDs, and stop reason are written to the ledger.

The sophistication belongs in how claims are challenged and evidenced. The final control rule should be simple enough to audit in seconds.
