Most AI pipelines let the model write the answer. Mine doesn't.

The LLM proposes; a deterministic pipeline disposes — every model output passes a gate before it touches a number anyone acts on.

Test bed: my family's weekly grocery bill. Open source. 🧵
---
Three places a model earns its keep, three gates:

• Entity matching → verdicts cached in DuckDB; gold reads ONLY the cache. One LLM call per pair, ever; runs replay byte-identically.

• Narration → any number not in the fact pack = hard reject.

• Parser repair → 3/
---
Self-healing parsers, gated. When a site changes its payload, the model proposes a patched parser. Promoted only if it reproduces the old parser byte-for-byte on known-good raw files and yields schema-exact records from the new one. Fail = rejected and logged, no silent retry.
---
Why groceries? Because the failure modes are visible. Fuzzy matching once matched "chicken" to chicken crackers. The fix wasn't more AI — it was deterministic category guards BEFORE any model is consulted, then LLM adjudication only for the survivors.
---
The result: a phone app that says "Harris Teeter wins this week at $123.17 — Whole Foods would've been $169.27." Every number traces back to raw bytes. DuckDB + files + Task Scheduler on a $300 mini PC; no Spark, no vector store. MIT: https://github.com/hemangnagar/grocery_optimizer
